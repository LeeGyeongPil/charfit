# Count text the way the platform does

Models cannot count characters reliably, and counting with `len()` or a GSM-7 table written from memory is wrong for messaging: `é` is GSM-7 but `á`, `ã` and `ê` are not, one curly quote or no-break space turns a 160-character SMS into 67-unit UCS-2 parts, a two-unit character (`€`, `[`, an emoji) is never split across segments so a segment can end one unit early, and Python's `euc_kr` codec silently encodes Hangul that a Korean carrier cannot send. The script applies the real rules, so never count by eye and never quote a number you did not get from it.

1. Pick the profiles from the request and run `python3 scripts/charfit.py check --profile sms,kr-sms --json --lang en "TEXT"` (the path is relative to this skill's folder; if your working directory is elsewhere, as in Codex, prefix it with the absolute path of the folder that holds this SKILL.md and run that exact command, never recount by hand). Use `--lang ko` when the user writes Korean. Profiles: `sms` (one segment; `sms:3` allows 3), `kr-sms` (90 EUC-KR bytes), `kr-lms` (2,000 bytes), `utf16:N` (HTML `maxlength`), `utf8:N` (API or database byte cap), `chars:N` (code points), `x-post` (280 weighted). Combine them with commas.
2. For a long or multi-line text, save it to a UTF-8 file and pass `--file PATH`; `-` reads standard input. If TEXT starts with a dash, put `--` before it. To just see every measure, run `count` instead of `check`.
3. For several messages (templates, translations, a campaign), do not loop or add up by hand: pass the whole file at once with `python3 scripts/charfit.py check --profile sms --jsonl FILE --json --lang en`. The file has one JSON object per line, `{"id": "es-otp", "text": "..."}` (`id` is optional; the line number is used without it). If the user's file has another shape, write such a file with a few lines of code that only copy the texts, then run the script on it. The output has one entry per item in `items` and a `totals` object: `totals.sms.segments` (billed segments of all items, each sent once), `totals.sms.ucs2` and `totals.sms.gsm7` (how many items use each encoding), `totals.sms.multi_segment` (items with 2 or more segments), `totals.kr_class` (how many items are `SMS`, `LMS`, `OVER` or `FAIL` for a Korean profile), `totals.failed_ids`. Report each of these totals as printed, next to the label the script gives it (for example "14 items with 2+ segments"); do not add up per-item values yourself.
4. Exit code 0 means every profile passed, 1 means a limit is exceeded. Read `results[].over` for the excess and `culprits` for the characters (`index` is the 0-based code point position, `codepoint` is `U+XXXX`). A culprit with reason `not_gsm7` is the character that switched the message to UCS-2 (it may be invisible, such as a no-break space); `not_in_ks_x_1001` and `unencodable` mean a Korean carrier cannot send it, and the item's `kr_class` is `FAIL`: name every such character with its `index`, even when Python's own codecs accept the text. `segment_starts` lists where each SMS segment starts as a 0-based code point index into the text (segment 1 is `segment_starts[0]`, segment 3 is `segment_starts[2]`); these are character positions, not multiples of 153 or 67, and the human output shows them as `part N: index I`. `boundary_extra` above 0 means the SMS needs that many more segments than `units / per_segment` because of the no-split rule; `segments` is the billed number.
5. To make an SMS fit in GSM-7, run `python3 scripts/charfit.py fix-sms --json --lang en "TEXT"`, or `python3 scripts/charfit.py fix-sms --jsonl FILE --json --lang en` for a file. It replaces curly quotes, en and em dashes, the ellipsis (`…` becomes `...`, two units longer) and odd spaces, recomposes decomposed accents, and then measures the result again: `after` is the cleaned text, `remaining` are characters (emoji, accented letters outside GSM-7) with no safe replacement. For a file, `totals.before` and `totals.after` give `segments`, `gsm7` and `ucs2` over all items and `totals.still_ucs2_ids` the items that stay UCS-2. A cleanup can add a segment (`...` is longer than `…`), so use `after` as printed. It never edits your text or file.
6. Loop: draft, `check`, change only what the culprits or `over` point at, `check` again, and stop only when the script exits 0 for the profiles the user asked about. When asked for several variants, run `check` on each one (or on a JSONL file of them) and quote its value.
7. Report values exactly as the script printed them (segments, totals, segment starts, bytes, culprit positions), and say the encoding when it is surprising ("UCS-2 because of U+00E3 at index 9"). Do not convert a number by arithmetic of your own or recount to double-check it; for a price, multiply the script's segment total by the price per segment. For a byte count, Python's `len(text.encode("euc_kr"))` is not the carrier's number either (see the culprits).
8. If the script exits with code 2, quote its `charfit: error:` line as is. It already says how to fix the input, for example the list of known profiles or the JSONL line that is broken. If the user asks for a platform that has no profile (for example a messenger template), say it is not supported, do not guess a limit with another profile, and name the profiles that exist.
9. If the script does not run (a traceback, no output, a file it cannot find) or prints something that does not fit the text (for example no segments for a long text), fix the command and run it once more. If it still fails, tell the user the checker failed and what it printed, and stop. Do not fall back to counting by hand or with code of your own: a hand-written GSM-7 table or segment loop is exactly the count this skill replaces, and its numbers must not be reported as the answer.

`x-post` follows X's published weights (links 23, Hangul 2, NFC first) and was checked against the twitter-text 3.1.0 library, but emoji sequences and country-code file names are an approximation, not a guarantee. Rules, sources, the GSM-7 accent table and known limits (no per-country GSM tables, no recipient-pays 152/66 limits, no grapheme counting) are in `references/rules.md`; read it only when a result is surprising or the user asks how a number was derived.
